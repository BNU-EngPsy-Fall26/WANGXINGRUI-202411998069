# 🦑 鱿鱼游戏：玻璃桥信号检测论（SDT）实验

一个**单文件、纯前端、零依赖**的交互式心理学实验网页。用《鱿鱼游戏》的玻璃桥场景，把信号检测论（Signal Detection Theory）里的
**辨别力 d′** 与**判断标准 c** 变成一个能亲手玩出来的游戏。

> 踩对玻璃 → 活下去；踩错 → 玻璃碎裂、坠入深渊，游戏立刻结束。
> 你能在摔死之前，分辨出哪块更亮吗？

## 🎁 加分项实现

### ① 交互式概念可视化 —— 「SDT 概念实验室」

结果页内嵌两张联动的 SVG 图，配两个滑块，把 SDT 里最抽象的两个概念变成可以拖着看的图。

**左图 · 信号分布 vs 噪音分布**

- 画出噪音分布 `N(0, 1)`（粉）与信号分布 `N(d′, 1)`（绿），两条曲线的**重叠程度随 d′ 变化**
- 白色虚线是判定标准 `x_c`，它右侧的两块阴影分别是 **P(FA) 虚报区**（粉）与 **P(H) 击中区**（绿）
- 基线下方用双箭头标出 d′ 的实际长度

**右图 · ROC 曲线**

- 理论 ROC 曲线：**曲线弯不弯完全由 d′ 决定**（d′ 越大越向左上角凸起）
- 白色圆点 = 当前滑块的工作点：**它与原点的相对位置由 c 决定**，拖动 c 时白点会沿着同一条 ROC 曲线滑动
- 空心红圈 = 本局实测的 (P(FA), P(H))，点一下「复位到实测值」即可与白点重合，直观验证理论模型对数据的拟合

**推导**（写在代码注释里）

```
d′ = Z(H) − Z(FA)，其中 Z(H) = d′ − x_c，Z(FA) = −x_c
代入 c = −0.5·[Z(H) + Z(FA)]  ⇒  x_c = c + d′/2
```

滑块初始值 = 玩家本局的实测 d′ 与 c，所以复位后「理论点」与「实测点」会重合。

> **教学价值**：拖动 d′ 时 ROC 曲线变形，拖动 c 时工作点沿曲线滑动 ——
> 这正好把「敏感度（d′）」与「反应偏向（c）」这两个常被混淆的概念在视觉上彻底分开。

### ② 多局数据对比 / 排行榜

- 每局结束后把 `{时间, 难度, 试次数, 结局, d′, c, 正确率}` 存入 **localStorage**（键名 `squid-sdt-history-v1`）
- 结果页展示：
  - 汇总 KPI：总局数、**最佳 d′**（带 🏆 标记）、按难度分组的平均 d′
  - **迷你条形图**：每局一根柱子，高度按 d′ 绘制，负值用粉红柱标出，最佳一局高亮
  - **明细表**：局次 / 难度 / 有效试次 / 结局 / d′ / c / 正确率 / 时间，最新排最上
  - 「清空历史记录」按钮
- 最多保留最近 30 局

**对比不同难度的平均 d′，可以直接看到「难度 → 辨别力」的效果**，反过来也验证了难度参数的设计是否合理。

> ⚠️ **重要实现细节**：以 `file://` 协议打开时（也就是双击 index.html 的场景），
> 部分浏览器（尤其 Safari）会抛出 SecurityError 禁用 localStorage。
> 因此所有读写都包在 `try/catch` 里，**失败时自动降级为「本次会话内存保存」**，
> 并如实提示玩家「当前环境禁用了本地存储」—— 存储问题绝不会影响实验本身。

## 🎲 试次是怎么生成的

```
每个试次：
  1) 掷骰子决定强化玻璃在哪一侧 —— 左侧 30%（P(S)=0.30）、右侧 70%
  2) 两块玻璃各得到一个亮度值
       亮度 = 基础亮度 92 + (是强化玻璃 ? Δ : 0) + 随机感知噪声(±σ)
  3) 玩家点击一块玻璃
       · 踩中强化玻璃 → 通过，850ms 后进入下一试次
       · 踩中普通玻璃 → 玻璃碎裂并坠落旋转，1500ms 后跳转结果页，本局结束
```

一共最多 **20 个试次**；中途坠落则提前结束，已完成的试次全部计入统计。

### 难度 → d′ 的映射

难度**不靠作弊**，而是通过两块玻璃的真实亮度差 Δ 与叠加其上的随机感知噪声 σ 来控制的：

| 难度 | 亮度差 Δ | 感知噪声 σ | 效果 | 预期 d′ |
|---|---|---|---|---|
| 简单 | 78 | ±6 | 强化玻璃明显更亮、偏白偏绿，一眼可辨 | 高 |
| 中等 | 34 | ±14 | 需要盯着比较才能分辨 | 中 |
| 困难 | 10 | ±22 | 噪声足以吞掉亮度差，甚至让普通玻璃看起来更亮 | 低（接近随机） |

## 📐 SDT 计分与计算公式

### 2 × 2 矩阵的映射方式

玩家每次点击左边或右边，因此这是一个**二择一（2AFC）**任务。为了得到 Yes/No 判断矩阵，
按心理物理学的标准做法，把**「点击左侧」记为回答「是」**：

|  | 实际：左侧是强化玻璃<br>（信号 Signal，P(S)=30%） | 实际：右侧是强化玻璃<br>（噪音 Noise，P(N)=70%） |
|---|---|---|
| **踩左边**（回答「是」） | 击中 **Hit** ✅ 通过 | 虚报 **FA** ❌ 坠落 |
| **踩右边**（回答「否」） | 漏报 **Miss** ❌ 坠落 | 正确拒绝 **CR** ✅ 通过 |

因此：`信号总数 = Hit + Miss ≈ 30% 的试次`，`噪音总数 = FA + CR ≈ 70% 的试次`。
**坠落次数 = Miss + FA**，恰好等于所有的误判。

### 计算步骤

```
① 极值修正（对数线性修正，log-linear correction）
     P(H)′  = (Hit + 0.5) / (信号总数 + 1)
     P(FA)′ = (FA  + 0.5) / (噪音总数 + 1)

② Z 分数
     Z(H)  = Φ⁻¹( P(H)′ )
     Z(FA) = Φ⁻¹( P(FA)′ )

③ 核心指标
     d′ = Z(H) − Z(FA)                  ← 辨别力
     c  = −0.5 × [ Z(H) + Z(FA) ]       ← 判断标准（反应偏向）
```

### 为什么要做极值修正？

如果某一局你**一次都没虚报**（FA = 0），那么 P(FA) = 0，`Z(FA) = −∞`，d′ 会直接变成 `+∞` 而无法使用。
对数线性修正的做法是给每个格子的计数加 0.5、给分母加 1，使概率永远落在 **(0, 1) 开区间**内，
从而保证 Z 分数始终有限。

### Z 分数怎么来的？

`zScore(p)` 是自己实现的 **Acklam 算法**近似（标准正态分布反函数），精度约 `1.15e-9`，
分低尾 / 中段 / 高尾三段用有理多项式逼近，**不调用任何外部库**。

### 指标怎么读

| 指标 | 含义 | 解读 |
|---|---|---|
| **d′** | 你能不能**分辨**出哪块更亮 | d′ ≈ 0 表示完全在瞎猜；d′ 越大表示亮度线索越清晰。**只反映敏感度，与偏好无关。** |
| **c** | 你**敢不敢赌** | c > 0 偏保守（更常回答「否」，即多踩右边）；c < 0 偏冒进（更常回答「是」，即多踩左边） |

由于本实验的强化玻璃有 **70% 概率在右侧**，一个理性的玩家本来就应当把 c 推向正值 —— 这正是**先验概率影响判断标准**的直观体现。

## ⚠️ 一处重要的设计取舍（请先读这里）

最初的需求设定是：「**30% 的试次有强化玻璃，70% 的试次两块都是普通玻璃**」。

这个设定在数学上**无法成立为一个可玩的实验**：

> 若某试次两块都是普通玻璃，玩家无论踩哪一块都必然坠落。
> 于是每试次的死亡率 = 70% + 30% × 50% ≈ **85%**，
> 游戏会在第 1 ~ 2 个试次就结束，**永远收集不到 20 个试次，也就无法估计 d′ 与 c**。

因此本实现采用如下等价且自洽的方案：

> **每一阶恰好有一块强化玻璃**（这也正是《鱿鱼游戏》玻璃桥的原始机制），
> 把「30% 先验」落在**「强化玻璃出现在左侧的概率」**上（左侧 30%、右侧 70%）。

配合「点击左侧 = 回答『是』」的标准映射后：

- 信号试次 ≈ 30%、噪音试次 ≈ 70%，与对数线性修正公式完全对得上；
- d′ 与 c 的数学定义完整、无退化；
- **坠落率 = 你的误判率**，惩罚机制得以保留，游戏也真正可玩；
- 先验概率 30% / 70% 的不对称，反而让「判断标准 c 的偏移」成为一个可以亲手感受的现象。

如果确实需要原设定中「两块都是普通玻璃」的噪音试次，正确的做法是**增加第三个反应选项**
（例如「🚫 判定本阶无强化玻璃 · 不踩」）来承载「否」反应——这属于另一版设计，可在此文件基础上扩展。

## 🔧 可扩展的方向

- **加入第三个反应选项**，实现严格意义的 Yes/No 任务（见上文设计取舍）
